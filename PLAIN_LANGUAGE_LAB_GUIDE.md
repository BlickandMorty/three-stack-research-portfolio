# Plain-Language Guide

This guide explains the public projects without assuming that the reader is a programmer or researcher.

## The connected idea

The projects are not meant to show that I already know every technical field. They show one question from different angles:

> How can an AI-assisted research system find the right information, check its work, preserve where evidence came from, and admit when a test fails?

## Epistemos is the workspace

Think of Epistemos as a research desk. Notes, documents, search, citations, and AI assistance are different tools on the same desk. The goal is to keep the person in control of what the model can read and change.

## Instant Recall is the index

A library index does not “understand” every book. It helps you find likely matches and shows why they ranked highly. Instant Recall combines exact words, titles, and fuzzy text overlap so retrieval can be inspected.

## LivingBrain is the memory experiment

Ordinary storage keeps information until somebody deletes it. LivingBrain asks what happens if memory has strength: often-used information becomes easier to keep, neglected information weakens, and contradictions are surfaced.

The brain comparison stops there. It is software inspired by a few memory ideas, not a model of a real brain or evidence that a machine feels anything.

## Scientific Reasoning Audit Loops is the exam

Imagine a student answering science questions three ways:

1. Give the first answer.
2. Recheck every answer.
3. Recheck only after a narrow calculator-like test identifies the kind of mistake.

Self-review improved total accuracy, but it also changed three answers that had originally been correct. Verifier-gated review repaired fewer cases but did not reopen correct cases. The experiment is useful because it preserves both the improvement and the drawback.

## Unified Address Space is the filing system

Imagine that a science measurement, a security event, and an AI-evaluation note all use similar words. A flat pile can confuse them. A typed address says what kind of record it is, where it came from, and which revision it belongs to.

Typed addresses helped when the comparison removed type information. They did not help on a separate easy test where the model already answered every case correctly. Both outcomes matter.

## DataSight is the inspection sheet

DataSight checks a CSV for things worth reviewing: blanks, unusual values, and columns that do not match the expected pattern. It does not automatically declare that unusual data is wrong.

## Security Operations Lab is the practice range

The security work stays on my own computer and authorized lab targets. I capture traffic, inspect packets, compare scan results with Windows services, and write a short report. The point is learning investigation discipline, not pretending that a localhost exercise is professional penetration testing.

## Prompt Lab is the checklist

Prompts work better when they clearly state the goal, evidence, limits, approval boundary, and stopping rule. Prompt Lab collects the patterns I use for evaluation and AI-assisted work. A checklist can reduce careless mistakes, but it does not replace technical expertise.

## How to judge the work

For every project, ask:

- What exact question was tested?
- What was actually run?
- What result was saved?
- What failed or stayed uncertain?
- How much AI assistance was used?
- Can I explain the project without hiding behind technical language?

That is the standard I am trying to build toward.
